01 · 1.4 通信元语

用“操作前后每台设备拥有什么”理解通信

Point-to-point

A: [X] → B: [X]

send / recv 只指定发送方与接收方，常用于 Pipeline stage 之间传递激活。

AllReduce

[A] [B] → [A+B] [A+B]

每台设备最终都得到归约后的完整结果。

AllGather

[A] [B] → [A|B] [A|B]

把各设备分片收集为完整张量，不做归约。

ReduceScatter

[A₀|A₁] [B₀|B₁] → [A₀+B₀] [A₁+B₁]

先归约，再让每台设备只保留结果的一片。

ReduceScatter + AllGather 在张量结果上可组成 AllReduce；实际耗时仍取决于消息大小、算法、拓扑与能否重叠。

02 · 2.2 单卡

先用精度和 micro-batch 调整单卡账本

Mixed precision

减少每元素字节数

参数、激活或梯度的容量与搬运压力下降；合适硬件路径上计算也可能更快。

必须验证：高精度更新状态、归约精度、溢出 / 下溢与收敛。

Micro-batch + accumulation

降低单次激活峰值

减小 micro-batch，用更多 micro-step 补回相同 global batch。

代价：小 shape 可能降低算子效率，固定开销被重复支付。

global batch 固定：micro-batch ↓ → activation peak ↓ → accumulation ↑

若峰值主要来自参数、梯度或优化器状态，继续减 micro-batch 收益会迅速变小，应转向状态分片。

03 · 3.1 目标

先定义服务形态，再谈“更快”

在线流式

首 token 快，后续稳定

关注 TTFT、ITL / TPOT、端到端时延、P95/P99 与稳定并发。

在线非流式

在截止时间内完成

关注端到端时延、尾延迟、吞吐与超时率。

离线生成

尽快、尽便宜完成

关注总完成时间、总吞吐、设备时与单位输出成本。

同一个 token/s，可能在回答用户体验、整机产能或离线任务成本三个不同问题。

03 · 3.1 指标

指标名相同，计时边界也要写清

TTFT

请求到首个输出 token

这里包含网络、排队、prefill 与产生首 token 的执行时间。

TPOT

首 token 后的平均输出间隔

平均值会掩盖抖动，在线流式还要看 ITL 分布。

吞吐

明确分子与聚合范围

output / total tokens/s 或 requests/s；单卡、单副本还是整个服务。

稳定并发

不是“显存能塞多少”

是在给定到达分布与 SLO 下可以持续服务的并发。

可比较的结果 = 相同 workload + 相同统计口径 + 相同质量边界
只测服务端或模型阶段时必须另行标明 content/03 · 3.1

03 · 3.2 阶段特点

两段执行的粒度、依赖与瓶颈都不同

维度 Prefill Decode
每次处理 一段输入 token 每个活动请求的一个新 token
依赖关系 输入位置可在一次前向中并行处理 下一个 token 依赖上一个 token，步骤间串行
KV cache 为输入建立初始状态 每步读取已有 KV，并追加新的 KV
常见特征 工作规模较大，更容易形成较大矩阵计算 低 batch 时更易受权重 / KV 搬运与运行时开销影响
Prefill 重点

缩短长输入处理，避免干扰已有 decode。

Decode 重点

减少逐步开销，或让多个请求更高效共享执行。

03 · 3.4 Chunked prefill

把 D 的长 Prefill 拆成 D₁ / D₂，让 Decode 继续推进

step 1
decode Adecode Bdecode C
step 2
decode Adecode Cprefill D₁
step 3
decode Adecode Cprefill D₂
step 4
decode Adecode Ddecode E
换来的

缩小长工作块

A/C 不必等 D 整段 Prefill 完成，ITL 更容易受控。

没有消失的

D 的总工作量

分块不删除 FLOPs 或有效 KV；只是改变调度粒度。

块过小时

额外开销上升

调度、kernel 启动、历史 KV 读取增加，也可能延后 D 的 TTFT。

Prefill–Decode 解耦可进一步隔离资源，但会新增 KV 传输与路由；正文只把它列为进阶方向。

03 · 3.6 固定条件

单请求基准与服务基准回答不同问题

Single request

这条关键路径是否更短？

固定：模型、采样、输入/输出长度、精度、硬件、卡数、并行度、质量集、warmup 与计时边界。

报告：TTFT、TPOT、ITL 分布、端到端 P50/P95/P99、峰值显存与质量。

Service

在 SLO 下能稳定服务多少？

固定：到达过程、长度联合分布、请求率/并发、SLO、调度、KV pool、副本与每副本卡数。

报告：queue time、尾延迟、tokens/s、requests/s、稳定并发、KV 占用、失败率与 GPU-hours。

实验假设示例：BF16 低并发 Decode 的单步时间接近权重与 KV 搬运下界；只改变权重格式，验证 bytes、峰值显存、TPOT 与质量。
是否包含排队、编译、网络，必须明确写出；否则 TTFT 与端到端时延不可比较。
