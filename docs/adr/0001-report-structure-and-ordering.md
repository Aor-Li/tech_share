# 报告结构与章节顺序：按"度量→通讯→并行→优化"的依赖链重排

作者给的五块主题顺序不固定。我们决定按后一层依赖前一层的逻辑重排为六段，并首尾各加一页统领：

- **① 性能估计基础** — 显存占用 + 计算量/时间估计（含 roofline 直觉）
- **② 通讯原语与代价模型** — all-reduce / all-gather / all-to-all / p2p + α-β 代价模型
- **③ 序列维并行** — Ulysses / Ring-Attention（单列，因其本质是通讯模式，承上启下）
- **④ 训练并行范式** — DP/ZeRO、TP、PP、EP
- **⑤ 显存与计算优化** — 激活重计算(checkpoint)、混合精度、offload、FlashAttention、KV cache 及推理侧优化
- 开头 **全景地图**页，结尾 **组合成真实部署**页（用 Philoflow 16-GPU / minimax 举例）

**为什么**：通讯必须先于并行，因为所有并行范式的代价都建立在通讯代价模型之上；序列并行独立成章，因为 Ulysses/Ring 本质是通讯模式，是从"通讯"到"并行范式"的桥。此结构一旦定下，所有章节稿都挂在其上，故记录在案。
