## 本章定位

**如何分析一次大模型输出需要多少算力？**

1. 要算多少次浮点运算（FLOPs 估算）
2. 用什么数据格式算（精度体系）
3. 机器一秒能算多少（硬件算力）
4. 实际能拿到多少（MFU）

## 1.3 硬件算力

### 1.3.1 NVIDIA GPU

```text
算力峰值 = SM 数 × 每 SM 每周期 Tensor Core MAC 数 × 2 × 频率
```

### 1.3.2 代际数据

本节计划对比不同代 NVIDIA GPU 的性能数值。

### 1.3.3 数值锚点

> [待核验] **H100 SXM ≈ 1 PFLOPS BF16（稠密）**——记住这个数就够推大部分账。

### 1.3.4 算力估计的陷阱

> 以下硬件规则进入正文前需要核验。

1. 稀疏峰值通常是稠密峰值的两倍，宣传数字可能使用前者。
2. TF32 是 FP32 的计算入口之一，实际可使用 Tensor Core。
3. 标称频率不等于持续功耗下的实际频率。

## 1.4 MFU：从峰值到现实

### 1.4.1 公式

```text
MFU = 实际 FLOPs/s ÷ 峰值 FLOPs/s
```

MFU 与 HFU 的区别之一，是重计算的 FLOPs 是否计入分子。

### 1.4.2 典型数值锚点

> 下表全部待核验。

| 场景 | MFU |
| --- | --- |
| LLM 稠密训练 | 35–50% |
| LLM MoE 训练 | 更低 |
| LLM decode | < 5% |
| DiT 推理 | 天然较高（始终计算受限） |

### 视觉设计备注

- MFU 瀑布使用同一坐标并列展示 LLM decode 与 H3 流式推理，依次呈现“峰值 → 非 GEMM 算子 → 访存受限 → 通讯 → 流水气泡 → 实际 MFU”。两栏的损失构成应指向后续章节，兼作全篇路线图。
- 实时性预算表从目标帧率反推每秒 FLOPs，再探索“分辨率 × 步数 × 注意力形态 × 卡数”的可行组合。
- [待核验] 原始设想使用“24 fps 实时流式输出 = 每秒 6,048 token”和“单卡 220 PFLOPs / 9 分钟”作为预算锚点。
