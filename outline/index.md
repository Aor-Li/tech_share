# 报告主索引

## 报告简报

- 主题：大模型训练与推理中的 AI Infra 基础
- 目标听众：主要面向从事大模型算法与数据工作的同事；日常会接触训练配置、显存不足、吞吐波动或推理部署，但不要求具备系统或 CUDA 背景。
- 分享时长：最终控制在 30–60 分钟；准备阶段按 60 分钟完整版本组织，并为每章保留 30 分钟压缩路径。
- 首要场景：现场演讲
- 听众收获：能把常见训推现象与计算、显存、数据移动和通信约束联系起来；能做量级估算、读懂常见配置，并知道下一步该观察什么，而不是掌握底层实现细节。
- 范围与边界：以 GPU 上的 Transformer / DiT 训推为主；实例讲解默认先用 Qwen3-32B 或更基础、知名的 dense decoder-only 模型建立常规基线，再介绍 MiniMax H3 的差异。OLMo 不进入主讲。硬件微架构、通信算法实现、框架源码和完整调参手册不进入主讲。
- 交付形态：逐页演示的单文件 HTML，并提供连续打印降级

## 贯穿案例原则

- **先建立 dense LLM 基线**：实例默认先讲 Qwen3-32B，让听众先看到熟悉的 token 序列、训练 step 与 prefill/decode，再介绍 MiniMax H3 的不同工作单元和计算路径；不将 Qwen3-32B 表述为 Qwen 最新模型。
- **基础机制优先于型号一致性**：如果 Qwen 在某个机制上相对普通 dense Transformer 引入过多专有设计，则改用 Llama 等更基础、更知名的 dense decoder-only 模型，或直接使用无品牌的标准 Transformer 示意，不为保持单一型号而增加旁支解释。
- **再落到 MiniMax H3**：H3 是团队场景案例，但承担的是“基线之后的差异分析”，不在通用机制尚未讲清时抢先引入。
- **不介绍 OLMo**：主讲内容、案例卡和视觉中不设置 OLMo；仅当已有资料必须支撑某项事实时，把它作为页脚来源而不展开模型背景。
- 若后续替换基础模型，需要同步检查所有大纲、正文、视觉需求和资料映射。

## 面向听众的筛选原则

每个候选知识点按以下三级筛选，不追求 Infra 知识体系的完整性：

1. **讲清楚**：算法或数据同学会直接配置、观察或受其影响，并且一个简单模型能帮助日常判断。
2. **讲直觉**：需要看懂术语和存在原因，但无需掌握公式、算法变体或实现参数。
3. **不进入主讲**：偏底层实现、低频专项调优，或不能在当前时长内转化为可用判断；只在问答或补充资料中提供入口。

具体取舍如下：

| 层级 | 内容 |
| --- | --- |
| 讲清楚 | 工作负载与指标、GEMM/Attention 到模型级的 FLOPs 估算、NVIDIA GPU 理论时间下界、显存组成与参数量估算、峰值与带宽的区别、精度、batch/shape、数据供给、DP、FSDP/ZeRO、TP/序列切分的动机、重计算、量化、batching、cache、复制与切分、基础排障 |
| 讲直觉 | MFU/HFU 基本口径、Roofline、FlashAttention 的 IO 思路、卡内/卡间/跨机层次、AllReduce/AllGather/ReduceScatter、通信重叠、PP/EP、编译与 kernel 优化、推理调度 |
| 不进入主讲 | GPU 微架构细节、逐算子穷举、稀疏峰值与底层指令口径、Roofline 数学推导、ring/tree 成本公式、NCCL 参数、所有并行维度的组合公式、框架源码、CUDA Graph 实现、服务调度算法细节 |

“不进入主讲”不代表内容没有价值，而是避免它们抢占案例和直觉建立的时间。

## 整体组织原则

全篇采用“**先建立三类资源直觉，再进入训练和推理场景，最后收束为诊断方法**”的结构。

- 基础形成估算链：计算、显存/数据移动和通信合并为一个基础章；计算与显存讲到可做量级估算，通信保持直觉层。
- 场景承担主体：训练、推理两章合计仍占一半时间，优先回答听众日常会遇到的问题。
- 机制只讲一次：基础章解释峰值、带宽、张量生命周期和 collective 直觉；应用章只解释具体配置为何改变这些约束。
- 案例先于术语表：DP/FSDP/TP 等从“为什么单卡或简单 DP 不够”引出，不按缩写逐项穷举。
- 案例顺序保持一致：先用 Qwen 或更基础的知名 dense LLM 讲常规路径，再用 MiniMax H3 讲差异；H3 训练只比较双向生成训练、causal 化改造训练和 rollout 训练的计算差异，推理分别分析双向视频生成、流式视频生成和 prompt 插入流程。
- 保留可迁移方法：结尾只要求听众能完成“明确目标 → 做量级估算 → 看观测 → 选一个杠杆 → 验证”的闭环。

## 概念依赖

```text
模型结构、数据形状与目标指标
             ↓
  计算 / 显存与数据移动 / 通信直觉
             ↓
     训练配置          推理配置
             \        /
              估算—观测—验证
```

只保留三条必要依赖：先定义工作负载再谈快慢；先理解单卡资源约束再谈分布式；先理解 dense LLM 常规路径，再比较 H3 的训练与推理工作单元。
