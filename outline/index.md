# 报告主索引

## 报告简报

- 主题：大模型训练与推理中的 AI Infra 基础
- 目标听众：主要面向从事大模型算法与数据工作的同事；日常会接触训练配置、显存不足、吞吐波动或推理部署，但不要求具备系统或 CUDA 背景。
- 分享时长：最终控制在 30–60 分钟；准备阶段按 60 分钟完整版本组织，并为每章保留 30 分钟压缩路径。
- 首要场景：现场演讲
- 听众收获：能把常见训推现象与计算、显存、数据移动和通信约束联系起来；能做量级估算、读懂常见配置，并知道下一步该观察什么，而不是掌握底层实现细节。
- 范围与边界：以 GPU 上的 Transformer / DiT 训推为主；01 用无品牌结构建立通用资源方法，并可用 Qwen3-32B 与 MiniMax H3 的参数量做一次计算量级对照；02、03 分别用 Qwen3-32B 或更基础、知名的 dense decoder-only 模型建立训练和推理基线，再介绍 MiniMax H3 的差异。OLMo 不进入主讲。硬件微架构、通信算法实现、框架源码、profiler 教程和完整调参手册不进入主讲。
- 交付形态：逐页演示的单文件 HTML，并提供连续打印降级

## 贯穿案例原则

- **通用方法不绑定工作单元**：01 以标准 Transformer/DiT 建立公式；可用 Qwen3-32B 与 MiniMax H3 的参数量做一次 `2P`/`6P` 量级对照，但不展开训推工作单元。
- **每个场景先建立 dense LLM 基线**：02 先完成 Qwen/基础 dense LLM 的训练资源账本，03 先完成其 prefill/decode 推理账本；不将 Qwen3-32B 表述为 Qwen 最新模型。
- **基础机制优先于型号一致性**：如果 Qwen 在某个机制上相对普通 dense Transformer 引入过多专有设计，则改用 Llama 等更基础、更知名的 dense decoder-only 模型，或直接使用无品牌的标准 Transformer 示意。
- **再落到 MiniMax H3**：H3 在 02、03 中分别承担训练和推理的差异分析，不在通用机制或场景基线尚未讲清时抢先引入。
- **总览只定位案例角色**：00 可以展示案例顺序和核验后的同口径规模对比，但不展开结构、工作单元或资源账本。
- **不介绍 OLMo**：主讲内容、案例卡和视觉中不设置 OLMo；仅当已有资料必须支撑某项事实时，把它作为页脚来源而不展开模型背景。
- 若后续替换基础模型，需要同步检查 00、02、03 的大纲、正文、视觉需求和资料映射；01 不受品牌替换影响。

## 面向听众的筛选原则

每个候选知识点按以下三级筛选，不追求 Infra 知识体系的完整性：

1. **讲清楚**：算法或数据同学会直接配置、观察或受其影响，并且一个简单模型能帮助日常判断。
2. **讲直觉**：需要看懂术语和存在原因，但无需掌握公式、算法变体或实现参数。
3. **不进入主讲**：偏底层实现、低频专项调优，或不能在当前时长内转化为可用判断；只在问答或补充资料中提供入口。

具体取舍如下：

| 层级 | 内容 |
| --- | --- |
| 讲清楚 | 工作负载与指标、GEMM/Attention 到模型级的 FLOPs 估算、NVIDIA GPU 理论时间下界、显存组成与参数量估算、峰值与带宽的区别、精度、batch/shape、数据供给、DP、FSDP/ZeRO、TP/序列切分的动机、重计算、量化、batching、cache、复制与切分、场景内的基础验证 |
| 讲直觉 | Roofline、片上存储与 HBM、FlashAttention 的 IO 思路、卡内/卡间/跨机层次、AllReduce/AllGather/ReduceScatter、通信重叠、MFU/HFU 基本口径、PP/EP、编译与 kernel 优化、推理调度 |
| 不进入主讲 | GPU 微架构细节、逐算子穷举、稀疏峰值与底层指令口径、Roofline 数学推导、ring/tree 成本公式、NCCL 参数、所有并行维度的组合公式、框架源码、profiler 操作、CUDA Graph 实现、服务调度算法细节 |

“不进入主讲”不代表内容没有价值，而是避免它们抢占案例和直觉建立的时间。

## 整体组织原则

全篇采用“**总览定方向 → 通用资源方法 → 训练与推理场景 → 回到总览收束**”的结构。

- **基础章减负**：01 只定义计算、显存/数据移动和通信的通用估算方法；计算与显存讲到可做量级估算，数据移动与通信保持直觉层。
- **场景章承担主体**：02、03 分别拥有训练和推理的工作单元、指标、完整资源账本、Qwen/基础 dense LLM 基线、H3 差异与验证方法。
- **机制只讲一次**：01 推导通用公式和硬件约束；02、03 只代入场景形状和调用次数，不重新解释公式，但要完整展示场景账本。
- **案例先于优化术语**：每个场景先建立 Qwen/基础 dense LLM 基线，再从“放不下、算不快、扩展差或目标不匹配”引出配置，不按缩写逐项穷举。
- **H3 只讲相对差异**：训练只比较双向生成训练、causal 化改造训练和 rollout 训练；推理只比较双向视频生成、流式视频生成和 prompt 插入流程。
- **诊断不再独立成章**：00 负责最终闭环，02、03 分别把高频现象转成场景内的假设、单一改动和验证指标，不重复复盘案例。

## 概念依赖

```text
模型结构、数据形状与目标指标
             ↓
  计算 / 显存与数据移动 / 通信方法
             ↓
     训练资源账本       推理资源账本
             \         /
        估算 → 观测 → 选择杠杆 → 验证
                       ↓
                 回到总览地图
```

只保留三条必要依赖：先掌握通用资源方法再代入场景；每个场景先建立 dense LLM 基线再比较 H3；任何优化结论都要在固定工作负载、质量边界和目标指标下验证。
