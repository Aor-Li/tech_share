# 报告主索引

## 报告简报

- 主题：大模型训练与推理中的 AI Infra 基础
- 目标听众：主要面向从事大模型算法与数据工作的同事；日常会接触训练配置、显存不足、吞吐波动或推理部署，但不要求具备系统或 CUDA 背景。
- 分享时长：最终控制在 30–60 分钟；准备阶段按 60 分钟完整版本组织，并为每章保留 30 分钟压缩路径。
- 首要场景：现场演讲
- 听众收获：能把常见训推现象与计算、显存、数据移动和通信约束联系起来；能做量级估算、读懂常见配置，并知道下一步该观察什么，而不是掌握底层实现细节。
- 范围与边界：以 GPU 上的 Transformer / DiT 训推为主；01 建立通用资源方法并保留 Qwen3-32B 与 MiniMax H3 的计算量实例，02 用标准 Transformer 训练 step 建立单卡资源交换与多维并行直觉，03 用无品牌示意或主流模型建立推理基线，再按教学价值选择少量差异策略。需要实例时可以使用 Qwen3 或 MiniMax H3，但不要求将它们贯穿或与各章紧密绑定；只有 MiniMax H3 的专属策略需要同时满足“相对主流模型差异明显”和“值得介绍”。OLMo 不进入主讲。硬件微架构、通信算法实现、框架源码、profiler 教程和完整调参手册不进入主讲。
- 交付形态：逐页演示的单文件 HTML，并提供连续打印降级

## 案例使用原则

- **通用方法不绑定型号**：先用标准 Transformer/DiT 和变量化形状建立机制；需要具体参数、形状或工作负载时，可以使用 Qwen3/MiniMax H3 等已核验实例。
- **实例不承担贯穿义务**：某章使用了 Qwen3 或 MiniMax H3，不代表其他章节必须继续沿用或形成逐章对照。
- **场景先建立主流基线**：03 先完成标准 decoder-only Transformer 或资料完整的主流 dense LLM 推理账本；Qwen3 可以作为其中一个具体实例，但不是固定主线。
- **MiniMax H3 专属策略采用双重门槛**：普通参数或计算实例可以直接使用；只有展开型号专属策略时，才必须同时满足“相对主流模型差异明显”和“对应策略值得主讲”。
- **总览不预设型号对照**：00 只说明通用示意与可选案例的分工，不制作固定的模型规模对比。
- **不介绍 OLMo**：主讲内容、案例卡和视觉中不设置 OLMo；仅当已有资料必须支撑某项事实时，把它作为页脚来源而不展开模型背景。
- 若后续采用或替换具体模型，需要同步检查对应场景章、总览中的案例说明和资料映射，不反向修改通用方法。

## 面向听众的筛选原则

每个候选知识点按以下三级筛选，不追求 Infra 知识体系的完整性：

1. **讲清楚**：算法或数据同学会直接配置、观察或受其影响，并且一个简单模型能帮助日常判断。
2. **讲直觉**：需要看懂术语和存在原因，但无需掌握公式、算法变体或实现参数。
3. **不进入主讲**：偏底层实现、低频专项调优，或不能在当前时长内转化为可用判断；只在问答或补充资料中提供入口。

具体取舍如下：

| 层级 | 内容 |
| --- | --- |
| 讲清楚 | 工作负载与指标、GEMM/Attention 到模型级的 FLOPs 估算、NVIDIA GPU 理论时间下界、显存组成与参数量估算、峰值与带宽的区别、精度、batch/shape、数据供给、DP、FSDP/ZeRO、TP/序列切分的动机、重计算、量化、batching、cache、复制与切分、场景内的基础验证 |
| 讲直觉 | Roofline、片上存储与 HBM、FlashAttention 的 IO 思路、卡内/卡间/跨机层次、AllReduce/AllGather/ReduceScatter、通信重叠、MFU/HFU 基本口径、PP/EP、编译与 kernel 优化、推理调度 |
| 不进入主讲 | GPU 微架构细节、逐算子穷举、稀疏峰值与底层指令口径、Roofline 数学推导、ring/tree 成本公式、NCCL 参数、所有并行维度的组合公式、框架源码、profiler 操作、CUDA Graph 实现、服务调度算法细节 |

“不进入主讲”不代表内容没有价值，而是避免它们抢占案例和直觉建立的时间。

## 整体组织原则

全篇采用“**总览定方向 → 通用资源方法 → 训练与推理场景 → 回到总览收束**”的结构。

- **基础章减负**：01 只定义计算、显存/数据移动和通信的通用估算方法；计算与显存讲到可做量级估算，数据移动与通信保持直觉层。
- **场景章承担主体**：02 负责训练 step、单卡资源交换、多维并行与验证方法；03 负责推理工作单元、指标、主流 dense LLM 基线、按需选择的差异策略与验证方法。
- **机制只讲一次**：01 推导通用公式和硬件约束；02、03 只代入场景形状和调用次数，不重新解释公式，但要完整展示场景账本。
- **问题先于优化术语**：02 先用训练 step 和资源账本说明“放不下、跑不快或扩展差”，03 先建立 dense LLM 推理基线和目标指标，再引出配置；都不按缩写逐项穷举。
- **型号策略按价值筛选**：03 只保留相对主流方案明显不同、且能帮助听众做资源判断的策略；不预设 H3 或任何其他型号必须出现。
- **诊断不再独立成章**：00 负责最终闭环，02、03 分别把高频现象转成场景内的假设、单一改动和验证指标，不重复复盘案例。

## 概念依赖

```text
模型结构、数据形状与目标指标
             ↓
  计算 / 显存与数据移动 / 通信方法
             ↓
     训练资源账本       推理资源账本
             \         /
        估算 → 观测 → 选择杠杆 → 验证
                       ↓
                 回到总览地图
```

只保留三条必要依赖：先掌握通用资源方法再代入场景；训练先从单卡资源交换进入多维并行，推理先建立主流工作负载基线再判断是否需要差异案例；任何优化结论都要在固定工作负载、质量边界和目标指标下验证。
