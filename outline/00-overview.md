## 章节契约

- 唯一目标：用一张知识地图建立并最终回收“通用资源方法 → 训练/推理场景 → 估算、观测与验证”的全篇路径。
- 预期结论：先用与模型无关的计算、显存/数据移动和通信方法建立共同语言，再在训练与推理章中分别用 Qwen/基础 dense LLM 建立基线、用 MiniMax H3 分析差异；听众最终应能把一个问题转化为可验证的资源假设。
- 内容边界：开场只提供范围、章节关系和案例角色，结尾只收束方法；不在本章展开模型结构、工作单元、资源账本、优化方案或诊断教程。
- 输入：报告主题、目标听众、已确认的章节顺序和案例角色。
- 输出：开场导航，以及结尾可带走的“明确目标 → 估算 → 观测 → 选择杠杆 → 验证”闭环。
- 创作参考：总览不单独借用外部文章结构；导览关系和结尾闭环来自本报告已确认的章节内容。
- 事实依据需求：Qwen3-32B 的模型定位与基础规格使用 `FACT-002`；两者的同口径规模对比使用待核验的 `FACT-004`，补齐 H3 授权来源前不填精确数值，也不把“可比量级”写成“严格相等”。

## 开场导览

- 用“工作负载与目标 → 计算、显存/数据移动、通信 → 训练或推理选择 → 观测与验证”说明全篇关系。
- 01 只建立与具体模型和训推阶段无关的资源语言；02、03 分别完成训练与推理的工作负载、案例和配置分析。
- 开场先展示完整地图，但不提前解释缩写、公式或案例结论；结尾回到同一张图收束。

## 案例定位

全篇实例按“常规基线 → 团队场景差异”展开，但具体内容只进入 02、03：

- Qwen3-32B 用于建立算法与数据同学较熟悉的 dense LLM 训练和推理基线；不将其表述为 Qwen 最新模型。
- 如果 Qwen 在待讲机制上有过多专有设计，则换用 Llama 等更基础、更知名的 dense decoder-only 模型，或使用无品牌的标准 Transformer 示意。
- MiniMax H3 用于比较团队场景中的不同工作单元和执行路径，不承担通用机制的第一解释。
- 两个模型首次同屏时，只用一张统一刻度的规模对比图控制模型大小这一干扰因素；详细结构、输入和计算分别留到 02、03。
- OLMo 不进入主讲；必要时只作为事实来源出现在引用中，不介绍模型本身。
- Qwen3 的 thinking / non-thinking 只在相关推理内容中出现，不干扰训练与通用资源方法。
- 不为维持对照形式而强行套用不适合的概念。

## 结尾收束

结尾复用开场地图，只增加一条行动闭环：

1. 明确比较对象、质量边界和目标指标；
2. 估算主要计算、峰值显存、数据移动和必要通信；
3. 检查观测是否支持当前瓶颈假设；
4. 只改变一个最可能影响关键路径的杠杆；
5. 用相同条件验证收益、副作用与停止条件。
