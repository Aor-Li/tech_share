## 章节契约

- 唯一目标：让听众面对显存不足、GPU 利用率低、多卡扩展差或推理尾延迟高时，知道第一轮该估算什么、观察什么、尝试什么。
- 预期结论：先把现象映射到工作负载和资源约束，再选择一个最可能改变关键路径的杠杆；优化清单不能替代对照验证。
- 内容边界：基础诊断流程、常见现象映射、案例复盘；不讲 profiler 操作教程，不引入新技术。
- 输入：前文的工作负载、计算、显存/搬运、通信和目标指标。
- 输出：一个初步假设、一个候选动作、验证指标与停止条件。
- 创作参考：`REF-001`；整体结构调研见 `references/research/ai-infra-content-architecture.md`。
- 事实依据需求：本章不新增精确事实；案例沿用前章已核验材料。

## 内容路径

### 4.1 四步闭环

1. 明确比较对象：同一 workload、质量边界和目标指标。
2. 做量级估算：主要计算、峰值显存、数据移动和必要通信。
3. 看观测是否符合：GPU 是否在算、在等数据、在等通信，还是受调度/主机侧影响。
4. 一次改变一个主要杠杆，用相同条件验证收益和副作用。

### 4.2 五个常见现象的第一反应

| 现象 | 第一批检查 |
| --- | --- |
| OOM | 哪类张量在何时达到峰值；batch/shape、精度、重计算或分片谁最直接 |
| GPU 利用率低 | shape 是否过小、padding 是否过多、数据是否供得上、是否频繁同步 |
| 多卡扩展差 | 每卡计算粒度、通信频率、跨节点映射和不可重叠尾部 |
| 平均吞吐高但尾延迟差 | 请求长度分布、排队、batch 组成、状态池压力 |
| 优化后更快但结果变化 | 精度、近似算法、步数或工作负载是否已经改变 |

### 4.3 两个案例各走一遍

- Qwen3-32B：先用熟悉的 LLM 场景快速演示流程；若具体机制受 Qwen 专有设计干扰，则换用更基础的知名 dense LLM。
- MiniMax H3：用同一方法、不同工作单元演示不能机械套用 LLM 结论。
