## 章节契约

- 唯一目标：让听众从一次训练更新的资源账本出发，理解单卡配置和常见并行策略为什么存在，并能按“先确认哪里放不下或跑不快，再决定切什么”的顺序讨论方案。
- 预期结论：训练扩展没有免费的并行；混合精度、梯度累积、重计算以及对 batch、训练状态、层内张量、层、序列或专家的切分，都在交换显存、计算、通信、流水线空泡或训练稳定性。
- 内容边界：训练 step 与 batch 体系、简化计算/显存账本、step time 与吞吐、混合精度、梯度累积、Activation Checkpointing、DP、ZeRO-1/2/3、FSDP、TP、PP 及其典型调度、SP/CP、Ring Attention、Ulysses、EP 与 MoE All-to-All；不讲并行通信公式、框架 API、组合并行搜索、集群拓扑设计、调度算法实现、MiniMax H3 专门案例或 profiler 教程。
- 输入：模型与数据形状、目标 global batch、精度、单卡容量、卡数/节点数和训练吞吐目标。
- 输出：一次训练更新的简化资源账本、一张按切分维度组织的并行地图、每种方法的收益与代价，以及从现象到切分选择的判断路径。
- 创作参考：`REF-001`、`REF-003`、`REF-004`、`REF-006`。
- 事实依据需求：如使用具体模型、GPU、显存、吞吐或扩展效率数字，在正文前登记并核验；ZeRO stage、FSDP、PP 调度、Ring Attention、Ulysses 与 EP 的机制表述优先使用论文或官方文档复核。

## 内容路径

### 2.1 先拆开一个训练 step：数据如何变成一次参数更新

- 按执行顺序说明 forward、backward 和 optimizer step 各自读取、产生、保留或更新什么。
- 区分 micro-batch、gradient accumulation 和 global batch，用多个 micro-step 组成一次 optimizer update 的时间线建立统一口径。
- 沿用 01 的资源方法，把参数、梯度、优化器状态、激活和临时空间放进简化显存账本；把 forward/backward/update 放进计算账本，不重复推导公式。
- 用 step time、samples/tokens per second 说明“跑不快”，用峰值存活张量说明“放不下”；MFU/HFU 只保留识别口径，不展开指标推导。
- 收束为后续判断：问题来自单卡容量、单卡计算粒度，还是多卡后的通信与等待。

### 2.2 单卡先做三类资源交换

- **混合精度**：用更少字节和合适的硬件计算能力换容量与速度，同时保留数值稳定性边界。
- **micro-batch 与梯度累积**：减小单次 forward/backward 的激活峰值，在不改变目标 global batch 的前提下增加 micro-step 数；说明它缓解容量但不会凭空减少总工作量。
- **Activation Checkpointing**：只保存部分激活，在 backward 时重算其余激活，用额外计算和更长 step time 换显存。
- 用同一个单卡示例并列三种方法改变了哪些账本项，避免把配置项讲成相互独立的技巧。
- 保留数据形状、padding/packing 和数据加载对计算粒度与 GPU 等待的提醒，但不展开数据管线优化。

### 2.3 多卡并行先问“切什么”

- 用一张总图列出六个切分对象：batch、训练状态、层内张量、层、序列/上下文和专家。
- 对每种方法统一回答四个问题：切分什么、解决什么问题、引入什么通信、主要代价是什么。
- 说明这些维度可以组合，但主讲先逐一建立直觉，不介绍多维并行乘积、自动搜索或集群映射。
- 建立选择顺序：完整副本放得下先考虑 DP；训练状态放不下再分片状态；单层、层数、序列或专家成为瓶颈时再切对应维度。

### 2.4 切 batch 与训练状态：DP、ZeRO 和 FSDP

- **DP**：每卡保留完整模型并处理不同 micro-batch，backward 后通过 AllReduce 同步梯度；收益是提高数据吞吐，代价是模型与训练状态仍被复制。
- **ZeRO-1/2/3**：用同一张分层图依次加入优化器状态、梯度和参数分片，展示每推进一级少复制了什么、运行时必须重新聚合什么。
- **FSDP**：把“参数分片、计算前聚合、计算后释放、梯度归并”画成生命周期，说明它与传统完整副本 DP 的差异，并避免陷入 API 和实现版本。
- 用固定 global batch 的小例子区分总工作量、单卡工作量、单卡状态和通信变化。

### 2.5 切层内张量：Tensor Parallelism

- 以 Transformer 中一个线性层或 MLP 为例，把权重矩阵沿列或行切到多卡，展示每卡计算的局部张量。
- 说明 TP 直接降低单层参数和中间结果的单卡占用，也能并行单层计算，但会在层内频繁引入聚合或归并通信。
- 用一张“局部计算 → collective → 恢复下一算子所需布局”的示意图建立原理，不推导通信量公式。
- 强调适用判断：当单层本身放不下或希望并行单层计算时考虑 TP，而不是仅因为有多张卡就使用。

### 2.6 切层：Pipeline Parallelism

- 把连续层分配到不同 stage，通过 micro-batch 流水执行，先展示“切层解决容量、stage 之间传递激活”的基本机制。
- **GPipe**：先连续 forward 再连续 backward，用时间线直观看到首尾空泡和较多在途激活。
- **1F1B**：进入稳定阶段后交替一次 forward、一次 backward，用同口径时间线比较空泡和激活存活量。
- **interleaved 与 zero-bubble**：只作为继续减少空泡、改善 stage 利用率的演进方向形成识别能力，不展开具体调度规则与正确性条件。
- 强调 PP 的新问题是 stage 平衡、流水线空泡和跨 stage 依赖，而不是免费的层数切分。

### 2.7 切序列或上下文：SP、CP、Ring Attention 与 Ulysses

- 先说明术语边界：SP 常与 TP 配合分摊序列方向的激活；CP 进一步让长上下文的 Attention 计算和 KV 状态跨设备分布，不把不同框架的命名强行视为完全一致。
- **Ring Attention**：每卡保留一段 query 和一段 KV，通过环形传递 KV 分块逐步完成局部 query 所需的 Attention。
- **Ulysses**：通过 All-to-All 在序列切分布局和 attention head 切分布局之间转换，让各卡完成局部 Attention 后再恢复布局。
- 用两张数据流示意图回答“数据如何移动、每卡何时拥有足够输入”，不展开通信轮次、负载公式和具体 kernel。
- 连接长文本、长视频时空 token 场景：收益是分摊长序列激活与 Attention，代价是序列维度上的通信与同步。

### 2.8 切专家：Expert Parallelism

- 以 MoE 层为例，把不同专家放到不同设备；其他层仍可复制或使用别的并行方式，但组合细节不进入主讲。
- 展示 token routing → All-to-All dispatch → 本地专家计算 → All-to-All combine 的完整数据流。
- 说明 EP 分摊专家参数与专家计算，但代价是 All-to-All、token 负载不均、容量限制和路由等待。
- 只建立“为什么需要 EP、为什么容易受通信和负载均衡影响”的识别能力，不展开路由算法和辅助损失。

### 2.9 用资源交换表完成选择

- 按 batch、状态、层内张量、层、序列和专家六行汇总：主要节省的单卡资源、增加的通信、可能新增的等待，以及最适合解决的问题。
- OOM 时先定位峰值来自激活还是训练状态，再比较 micro-batch、重计算、状态分片或对应维度切分。
- 单卡利用率低时先检查计算粒度、padding 和数据供给；多卡扩展差时再检查 collective、流水线空泡、负载不均和不可重叠等待。
- 固定模型、数据、global batch、精度与质量边界，只改变一个杠杆并用 step time、吞吐和峰值显存验证。
