## 1.3 硬件算力

### 1.3.1 Nvidia GPU

```
算力峰值 = SM 数 × 每 SM 每周期 Tensor Core MAC 数 × 2 × 频率
```

### 1.3.2 代际数据

- [CHART] 展示不同代 NV 显卡的性能数值差异

### 1.3.3 数值锚点

> **H100 SXM ≈ 1 PFLOPS BF16（稠密）**——记住这个数就够推大部分账。

### 1.3.4 算力估计的陷阱

1. **稀疏峰值 = 稠密 × 2**，宣传数字常用前者
2. **TF32 只是 FP32 的入口**，实际走 Tensor Core
3. **标称频率 ≠ 持续功耗下的实际频率**

## 1.4 MFU：从峰值到现实

### 1.4.1 公式

```
MFU = 实际 FLOPs/s ÷ 峰值 FLOPs/s
```

MFU vs HFU 的区别：重计算的 FLOPs 算不算进分子。

### 典型数值锚点

| 场景 | MFU |
|---|---|
| LLM 稠密训练 | 35–50% |
| LLM MoE 训练 | 更低 |
| LLM decode | **< 5%** |
| **DiT 推理** | **天然较高**（始终计算受限） |

### 🎛️ 动态图 · 双栏 MFU 瀑布

- **左栏 LLM decode**、**右栏 H3 流式**，并列同一坐标

## The Takeaways

### 📊 静态图 · 一页速查卡

H3 与 LLM **双栏对照**的公式与数值锚点：

| | LLM | H3 / 视频 DiT |
|---|---|---|
| 每 token 前向 | 2N | 2N_eff（注意 AdaLN） |
| 训练总量 | 6ND | 6N_eff·D，无步数乘子 |
| attn 占比 | s/(6h) ≈ 0.17 | 0.94 ~ 10 |
| 推理成本 | 2N/token | steps × cfg × (...) |
| decode/流式瓶颈 | 访存受限 | **计算受限** |
