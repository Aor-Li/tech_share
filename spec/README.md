# Agent 辅助编写规范

本文件是 TechShare 代理工作流的唯一规则来源。每次任务开始时完整阅读，再按任务类型执行对应分支。项目术语见 [`CONTEXT.md`](../CONTEXT.md)，关键架构取舍见 `docs/adr/`。

## 核心模型

- 本项目服务当前技术分享，由用户担任唯一内容负责人，代理负责执行与检查。
- 写作按“创作参考与事实依据 → 大纲 → 正文 → 报告快照”的顺序推进。
- 大纲是结构、章节目标与核心结论的权威来源；正文是具体表达的权威来源；`report.html` 是派生的报告快照，不反向覆盖前两者。
- 现场演讲是首要场景；报告快照采用逐页演示，并提供连续打印降级和会后阅读能力。
- 项目保持纯文档结构，不引入构建工具、框架、数据库或额外运行时。

## 工作区

- `outline/index.md`：报告简报、章节顺序和大纲状态的主索引。
- `outline/NN-章节名.md`：单章目标、预期结论、参考映射、视觉需求和制作清单。
- `content/README.md`：正文文件索引和正文状态。
- `content/NN-章节名.md`：已确认章节大纲对应的逐章正文，编号与大纲一致。
- `references/`：创作参考、事实依据、原始资料和来源索引。
- `report.html`：汇总已确认内容的单文件报告快照。
- `CONTEXT.md`：项目统一术语表，只记录领域语言，不记录流程规则。
- `docs/adr/`：少量、难以逆转且存在真实取舍的架构决策。

## 状态模型

- 大纲与正文：`草拟 → 待确认 → 已确认 → 需回修`。
- 事实依据：`待核验 → 已核验`；创作参考不使用核验状态，只记录是否采纳及借鉴用途。
- 报告快照：`未同步 → 已同步 → 已验收`。
- `outline/index.md` 记录每章大纲状态，`content/README.md` 记录每章正文状态，`references/sources.md` 记录资料类型和核验信息，`report.html` 只记录自身状态。
- 不创建额外总任务表；状态必须紧贴其权威文件。

## 每次任务

1. 检查当前分支、工作区和任务涉及的文件，识别确认基线、受保护内容及现有未提交改动。
2. 将任务归入一个主要分支；跨分支任务按“资料 → 大纲 → 正文 → 报告”的顺序处理。
3. 只修改用户指定的范围；章节是执行单位，小节是确认单位。
4. 修改前记录本轮受保护内容；修改后更新对应状态和受影响的下游状态。
5. 完成对应分支的检查项，并说明改动、校验结果、工作区状态和仍待确认的信息。

## 资料

### 收录原则

- 调研、规划或写作中发现会影响内容结构、事实判断、示例选择或视觉设计的有价值资料时，在当轮任务中将其纳入 `references/`；至少在 `references/sources.md` 登记稳定来源、资料类型、相关章节、具体用途和采纳或核验状态。
- 原始资料内容过多、许可不适合保存全文或本地副本没有必要时，不要求完整收录；保留稳定链接、与本项目相关的摘要、关键内容定位（章节、页码或锚点）以及必要的摘录说明即可。

### 创作参考

- 每章规划前优先调研约 3–5 篇高质量类似文章，对比其结构亮点、内容覆盖、图表思路和本章适配性。
- 在 `references/sources.md` 中使用稳定的 `REF-NNN` 编号，并记录借鉴用途和采纳状态。
- 默认只提取叙事方法、内容范围和视觉思路；正文重新表达，图表根据本报告重新绘制。
- 直接复用文字或图表前必须确认许可与署名要求，并在报告中标注来源。

### 事实依据

- 只有精确数字、计算结果、直接引语、模型或硬件规格、性能对比及高风险强结论必须核验。
- 在 `references/sources.md` 中使用稳定的 `FACT-NNN` 编号，记录对应章节、可核验主张、具体定位和核验状态。
- 一般概念解释、叙事组织和教学类比可以综合多份资料重新表达，不要求逐句引用。
- 无法核验的高风险信息标记“待核验”，不得写成确定事实。

完成条件：创作参考说明了借鉴什么，事实依据能定位到原始材料，高风险信息没有未标记的不确定性。

## 大纲

- 规划阶段只编辑 `outline/`，不扩写 `content/` 或 `report.html` 正文。
- 主索引写清主题、目标听众、分享时长、听众收获、范围边界、章节顺序和每章状态。
- 每个章节文件只服务一个主要目标，并包含一句预期结论、内容边界、参考映射、视觉需求和制作清单。
- 视觉需求说明教学目的、所需材料、展示形式及打印降级；制作清单与章节结论、事实内容分开维护。
- 章节文件顶部维护迭代状态表，记录小节状态及本轮约束，不给每个段落添加永久状态标签。

完成条件：所有计划章节均有编号、唯一目标、预期结论、参考需求、视觉需求和确认状态。

## 正文

- 用户确认章节大纲后才创建对应正文；每次只处理用户指定的一章。
- 每章使用 `NN-章节名.md`，编号与大纲一致，并在文件顶部维护小节状态和本轮约束。
- 先给结论，再给解释、依据和短小可复现的示例；写清适用边界，并区分事实、推断与个人观点。
- 直接迭代当前章节文件，用 Git 保存历史，不创建 `v2`、`final` 等平行版本文件。
- 保留用户已确认或本轮明确保护的内容；修改完成后清理已经失效的临时约束。

完成条件：本章只有一个主要目标，高风险信息均已核验或标记，适合现场讲解和屏幕阅读。

## 大纲与正文迭代

- 大纲管理“讲什么、为什么讲”，正文管理“具体怎么讲”；改到哪一层，就更新到哪一层，不机械地同时修改两者。
- 只调整措辞、例子、一般解释或篇幅时，只修改正文；大纲保持已确认，正文重新进入草拟或待确认，报告快照变为未同步。
- 调整章节目标、核心结论、章节顺序或增删章节时，先修改并重新确认大纲；对应正文标记需回修，报告快照标记未同步。
- 新增创作参考本身不改变确认状态；实际采用其结构或内容时，按影响范围修改大纲或正文。
- 事实依据被判定错误时，相关正文标记需回修；若影响核心结论，大纲也标记需回修；报告快照标记未同步。
- 正文与大纲不一致但大纲仍然正确时，只修正文。

## 确认基线与 Git

- “已确认”必须来自内容负责人的明确确认，代理不得自行判定。
- 某章或小节标记已确认时，创建只包含该确认范围的普通 Git 提交，作为可恢复的确认基线。
- 提交前核对当前分支、工作区和目标范围；不得混入无关改动。
- 后续迭代以最近确认提交为基线；不为版本历史创建重复文件、标签或临时分支。
- 未经用户要求，不自动提交尚未确认的草稿、框架调整或报告快照。

## 报告快照

- 只有用户要求预览或交付时，才把已确认且已提交的大纲与正文同步到 `report.html`。
- 文件顶部用 HTML 注释记录快照状态、确认基线和包含章节；状态值使用 `outdated`、`synchronized`、`accepted`，同步内容变化后先标记 `outdated`。
- 报告采用逐页演示，每页围绕一个结论或视觉重点，支持目录跳转和键盘翻页。
- 动态视觉仅用于解释过程、状态变化或参数关系，使用内嵌 SVG、CSS 或少量 JavaScript，并始终提供静态打印降级。
- `report.html` 保持单文件、可离线分享；离线所需图片使用内嵌 data URL，不依赖外部运行时。

报告从已同步变为已验收前，必须确认：

1. 只包含指定确认基线中的章节，快照元数据与实际 Git 基线一致。
2. 可离线打开，目录、逐页导航和键盘翻页正常。
3. 常见 16:9 屏幕下无明显溢出、遮挡或信息墙。
4. 打印内容完整、分页合理，动态图保留静态核心信息。
5. 没有“待填写”、制作待办或调试标记。
6. 直接复用材料已署名，高风险信息已经核验或明确标记。

## 结构维护

- 本文件是协作规则的唯一来源；其他文档只保存术语、模板、状态、内容或架构决策，不重复维护流程规则。
- 目录、命名或状态模型变化时，同步检查主索引、正文索引、来源索引和报告快照标记。
- 完成条件：目录职责无冲突，差异范围准确，工作区状态已向用户说明。
