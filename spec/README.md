# Agent 辅助编写规范

本文件是 TechShare 代理工作流的唯一规则来源。每次任务开始时完整阅读，再按任务类型执行对应分支。

## 工作区

- `outline/`：规划主题、章节目标、核心结论和资料映射。
- `content/`：存放已确认大纲对应的逐章正文。
- `references/`：存放原始资料、代码引用和来源索引。
- `report.html`：汇总已确认内容和样式的最终单文件交付物。

项目保持纯文档结构，不引入构建工具、框架、数据库或额外运行时。

## 每次任务

1. 检查工作区状态和任务涉及的现有文件，识别用户已确认的内容。
2. 将任务归入下方一个主要分支；跨分支任务按“资料 → 大纲 → 正文 → 报告”的顺序处理。
3. 只修改用户指定的范围，保留已确认内容与设计。
4. 完成对应分支的检查项，并说明改动、校验结果和仍待确认的信息。

## 任务分支

### 资料

- 将写作输入放入 `references/`，并在 `references/sources.md` 登记来源、用途和核验状态。
- 保留原文；事实、数字和引语必须能追溯到具体来源。
- 来源缺失或结论不确定时标记“待核验”，不推测补写。
- 完成条件：资料位置明确，来源索引可追溯，引用限制已记录。

### 大纲

- 规划阶段只编辑 `outline/`，不扩写 `content/` 或 `report.html` 正文。
- 写清主题、听众、时长、范围，以及每章唯一目标、一句预期结论、证据需求和来源映射。
- 完成条件：所有计划章节均有编号、目标、预期结论、来源需求和确认状态。

### 正文

- 用户确认大纲后才进入 `content/`；每次只处理用户指定的一章。
- 每章使用 `NN-章节名.md`，编号与 `outline/` 一致。
- 先给结论，再给解释、证据和短小可复现的示例；写清适用边界，并区分事实、推断与个人观点。
- 直接迭代当前章节文件，用 Git 保存历史；保留用户已确认的段落。
- 完成条件：本章只有一个主要目标，所有事实可追溯，没有未标记的不确定信息，且适合现场讲解和屏幕阅读。

### 报告

- 用户要求预览或交付时，才把已确认的大纲与正文同步到 `report.html`。
- `report.html` 保持单文件可分享；离线所需图片使用内嵌 data URL。
- 完成条件：HTML 结构有效，可直接用浏览器打开和打印，页面没有明显溢出、遮挡或信息墙。

### 结构与 Git

- 目录或协作规则变更应保持本文件为单一规则来源；其他文档只保留用途、模板或面向人的说明。
- Git 操作前核对当前分支、工作区和目标范围；提交只包含本次任务相关变更。
- 完成条件：目录职责无冲突，差异范围准确，工作区状态已向用户说明。
